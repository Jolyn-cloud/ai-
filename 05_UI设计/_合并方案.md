# 闪卡多页面 → 单文件合并方案

> 目标：将 闪卡首页/单卡/列表/章节统计/设置 5 个独立 `.html` 合并为一个 `闪卡原型.html`
> 单文件内 5 个视图 + 手机壳 + 顶部 tab + 右侧逻辑说明面板
> 日期：2026-08-26

---

## 一、现状调研结论

| 维度 | 发现 |
|---|---|
| CSS | 5 页共享 120+ 选择器**逐字一致**（.page/.content/.top-bar/完成结算全套/模态框），零冲突，可全量合并 |
| JS 函数 | 单卡/列表的 `showCompletion`(132行) 100% 相同；另有 13 对函数完全相同。仅 `restart/goNextChapter/goToPractice` 三处有视图差异 |
| ID | 首页/设置/章节统计 ID 与单卡/列表几乎全不冲突；首页×章节统计共用 `heroPct`/`heroFill`（2处小改）；单卡×列表共享 22 个"完成结算页"ID（语义相同，合并后保留一份） |
| 页面结构 | 均 `.page` 容器 + 内联 `<script>` + `闪卡题库.js` 数据层 |
| 跳转 | `location.href='xx.html'` 硬跳转 + URL 参数（?chapter/sub/topic/point） |
| 数据层 | `闪卡题库.js`(680K) 外部引用，5 页共享 |

## 二、合并架构

### 1. 视图容器（叠放 + 状态机）
```
<body>
  <div class="app-phone">           手机壳
    <div class="phone-screen">
      <div class="view" id="view-home">     首页视图
      <div class="view" id="view-single">   单卡视图
      <div class="view" id="view-list">     列表视图
      <div class="view" id="view-stats">    章节统计视图
      <div class="view" id="view-settings"> 设置视图
    </div>
  </div>
  <aside class="logic-panel">       右侧逻辑说明面板（贯穿所有视图）
</body>
```

### 2. 视图切换
```js
function nav(view, filter){           // 内部导航，替代 location.href
  FILTER = filter || null;            // 内存透传章节过滤
  showView(view);                     // 切换 active 视图
  syncMiniAppTab();                   // 同步顶部 tab 激活态
  if (VIEW_OPTS[view].onEnter) VIEW_OPTS[view].onEnter(FILTER);  // 进入钩子
  renderLogicPanel(LOGICS[view]);     // 右侧面板切对应逻辑
}
```

### 3. 数据状态
- `闪卡题库.js` **保持外部 `<script src>`**，不内联（避免 900K+ 单文件）
- 首页 `CHAPTERS`（10 章考点树，61KB）保留在首页视图脚本作用域，章节统计/设置通过数据层 `getChapterStats()` 读取
- `baseState`（今日队列+标记）仍由 `闪卡题库.js` 维护，单卡/列表/首页共用同一份

### 4. 命名空间（关键）
- **CSS 类名**：不改，全量合并（已证实零冲突）
- **共享 JS 函数**：去重为一份。`showCompletion` 等相同函数只留一个定义
- **视图差异函数**：
  - `restart()` → 内部判断当前视图，调 `init()` 或 `renderList()`
  - `goNextChapter`/`goToPractice` → 改为 `nav('single'/'list', {chapter})`，不跳外部页
- **ID 冲突**：
  - 首页 × 章节统计：`heroPct/heroFill` → 首页改 `homeHeroPct/homeHeroFill`，章节统计保持（或反向，定了为准）
  - 单卡 × 列表：完成结算页只保留一份（两者共用；切换时用同一套节点，不重复渲染）
  - 其余单卡/列表的"重复 ID"其实是**同一套共享组件**，合并后自然只存在一份
- **跨视图钩子**：`VIEW_OPTS = { home:{onEnter}, single:{onEnter}, list:{onEnter}, stats:{onEnter}, settings:{onEnter} }`
  - 各视图的 `render()/init()` 只在首次或其数据变化时执行，避免重复定义

### 5. 版本号（三处一致）
- `闪卡原型.html` **v1.0**
- 顶部 tab 右侧 + 逻辑面板 chip + 页脚 = 当前视图版本号（单卡 v3.0 / 列表 v2.8 / 首页 v2.5 / 章节统计 v1.5 / 设置 v1.2）

## 三、实施步骤（分 6 步，每步 L0-L2 + git 提交）

1. **git 基线**（已提交 `1ff4ba5`）
2. **骨架 + 尺寸容器** `闪卡原型.html`：手机壳 + 顶部 tab + 右侧逻辑面板 + 空视图切换状态机（可运行）
3. **移植首页视图**（DOM + 内联 JS 去重，含 CHAPTERS 数据）
4. **移植单卡 + 列表视图**（两者共享完成结算页，合并到 1 个视图容器，`restart/goNextChapter/goToPractice` 改视图感知，滑动/翻卡交互保留）
5. **移植章节统计 + 设置视图**（各自 ID 前缀消解冲突）
6. **收尾**：逻辑面板接好单卡逻辑说明 + 全量 L0-L2 测试 + git 提交

## 四、风险与兜底

| 风险 | 兜底 |
|---|---|
| JS 合并后作用域污染（同名函数覆盖） | 共享函数去重 + 每步 L0-L2 全量回归测试 |
| ID 冲突导致 getElementById 拿错节点 | 视图按命名空间前缀隔离 id |
| iframe 背景图引用失效 | 背景图路径保持相对引用 `bg-flashcard-home.png`（同目录） |
| 单文件过大（内存/编辑） | 数据层与考点数据维护外部（仅 DOM+逻辑合并）；考点树可后续抽成独立 js |
| 切换视图后状态错乱 | 每视图 onEnter 钩子负责渲染自身，共享数据留在数据层 |
